# Find incidents like the one in front of you

**Incident evaluation profile for [corpus-wide discovery](30-corpus-discovery.md).** An agent can use the existing read-only `find` across asset kinds, or narrow it to similar incidents. Start with admitted incident reports and their linked evidence in the corpus of one realm. Information retrieval ranks leads. A fix for the current incident requires its own observations, applicable conditions and the ordinary proposal or action gates. Citation integrity remains the first implementation priority.

## What the investigating agent does

A checkout service starts returning 500s after an API rollout. Older SDK clients fail while newer clients work. The agent knows that distinction but has no ticket ID. It sends symptoms, exact observed errors or symbols if available, affected service/repo, known client versions, time window and a small result budget. Leave the suspected root cause separate from observations. Search the pinned authorized context. Use declared service/dependency links as a restriction when the dependency inventory is reliable. If a narrow search is empty, widen within the same authorized scope and disclose the changed filter.

A proposed response returns at most three short handles by default, each with case revision, evidence role, match basis and an excerpt-sized explanation. Preserve contrary facts and time applicability. A reason describes observable evidence such as shared service or matched error term; a semantic ranking score is not a generated causal explanation. Expose a coarse coverage state (lexical only, hybrid ready, partial or unavailable) without exposing hidden object counts. The agent uses `peek` on the strongest candidate and a competing explanation. It follows the source span to the retained evidence, records its *current* discriminating observation, then chooses whether to prepare a citation. If the SDK error is absent in current telemetry, leave the old repair as a hypothesis.

| Proposed agent input | Example |
| --- | --- |
| Operation | `find` with intent `similar-cases`, budget 3, pinned realm, release and named context |
| Symptom | “Adding a response field makes older callers fail decoding” |
| Candidate | Historic SDK incident showing an unknown-field exception, with the affected version and a handle to the exact incident revision |
| Discriminator | A retry loop on the same endpoint can look similar to a user. Check decoder exceptions versus repeated continuation tokens. |
| No useful hit | Report the searched scope and retrieval coverage, then inspect current evidence. Zero returned rows cannot certify the absence of an analogue. |

## Data and retrieval contract

Use nominal ScopeCut, CaseRevisionRef, SpanRef, SearchProfile, IndexGeneration, CandidateHandle and AdmissionWitness. CandidateHandle and AdmissionWitness have separate private constructors. A handle binds visibility realm, release, named context, asset, immutable revision, representation and selector, evidence role, and scoped expiry. Query records bind mode, scope cut, canonical parameters, query-template hash, corpus generation, index manifest/profile, engine pin, ranker configuration and budget. For audits retain the ordered **actual returned** references and their reasons within policy, plus omissions. Replay retained results even if a future approximate run gives a different order.

Rank exact identifiers first when present. Use typo-tolerant lexical search for small spelling variation. Compare graph-scoped BM25, vectors alone and graph-scoped hybrid rank fusion. Use the old incident's report and admitted observations as retrieval text. Minimize chunk size around the timeline, symptom and discriminating condition; repeat stable case identity on each excerpt. Collapse multiple chunks of one case before spending all three slots on it. Current and superseded revisions remain distinguishable. Do not embed raw session logs, secrets, unreviewed learning drafts or outcomes that would be unavailable as of the query cutoff.

The backend ranks only the authorized view. Include ranking inputs such as BM25 corpus statistics, vector candidate windows, explanations and any published counts in that requirement. A final ACL filter alone does not establish that two otherwise identical visible corpora return the same list. Use a proven isolation partition or an adequately scoped ranker. When that is unavailable use a qualified scoped lexical path, or report unavailable. Never silently query a broader realm or call a remote embedding provider. Recheck access and retention on each `peek`. Never log restricted hit IDs. Do not try to retroactively erase knowledge already seen by an authorized reader.

## What must be proved

[Formal sources and receipts](../qualification/similar-cases/README.md) define a small candidate calculus. The predicate `Eligible(cut, policy, binding)` requires the correct realm, release, context, visibility and retained exact evidence. A hostile or approximate ranker can reorder, omit, duplicate or invent references. Only resolved eligible bindings can issue handles. Eligibility under the policy at issuance and at opening is required. Historical handles never silently upgrade to another revision.

| Property | Evidence and remaining work |
| --- | --- |
| Issued handles stay within eligible bindings. Open cannot substitute a different binding or survive revocation. An empty ranker can miss an eligible case. | Lean terms with arbitrary rankings and concrete witnesses. Five local propositional guard laws independently checked as a supplemental result. Lean 4.21 kernel receipt pending. |
| Authority depends only on the sequence of separately checked witnesses. Erasing arbitrary discovery/inspection operations preserves authority under the model. | An independent proof checker verified a structural-induction certificate for the two interpretations on every finite trace, of arbitrary length. Its six defining equations and induction/equality rules are visible in TraceErasure.mm. A companion Lean induction is supplied for review. Two traces with the same witnesses must reach the same authoritative state. A search can influence an agent's *choice* of future proposals. The theorem deliberately holds the witness sequence fixed. |
| Identical visible inputs produce identical public results under a fixed ranker/seed. | Lean factorization lemma. The adapter must prove it actually factors through the authorized projection. Shared ANN/IDF state, timing channels, and remote service behavior are outside the lemma. |
| Concurrent index build, cut changes, retrieval and revocation have explicit boundaries. | TLA+ actions and config, plus an independently executed finite Python reference. TLC replay, general TLAPS invariant proof (or reviewed discharge against an existing model), Verus adapter refinement and real WSL fault tests remain gated. |
| The result is relevant, cheap or a useful analogy. | Human judgments and controlled evaluation. A theorem about handles does not establish retrieval quality, equivalent root cause or token savings. |

Authority-neutral discovery does not need a per-hit Lean admission certificate. Enabling a policy, procedure or retrieval profile as authoritative design follows plan/25. A specific proposal made from discovered evidence still needs the previously qualified Lean rules, instance certificate, witness, predecessor, scope and authority.

## Index publication

One derived index alongside the selected corpus within its trust realm. No third authoritative database and no embeddings in the engineering ledger. Pin source cut, dependency closure, normalized input bytes, query/document formatting, chunker and tokenizer, model artifact/configuration and dimensions, distance/normalization, ANN and fusion settings, provider location and package digest. Track which eligible bytes have vectors. An index generation is immutable. The coordinator exposes it only after verifying its manifest and conditionally publishing for the intended cut/profile; track freshness separately from generation. Readers hold immutable pins. A stale builder cannot overwrite the active pointer. Revoked/expired handles are denied even when the old snapshot is retained.

Use a pinned local endpoint or externally supplied vectors computed under the approved local profile. A matching model name or dimension alone is insufficient. If embeddings are absent or the provider fails, report reduced coverage; lexical fallback uses the **same scope**. Never return zeros claiming semantic coverage. A model change creates a new derived generation. The original case, citation and historical manifest retain their identities. Distribution of a model or writing an active index is a separate provisioned operation. The proof abstracts a verified complete generation as an opaque epoch. Crash atomicity, ABA (re-selecting an older configuration), blob retention during garbage collection and reader leases need separate native tests with fresh generation identities and conditional heads.

## WSL experiment and admission gate

1. Freeze a blinded set of permitted, deidentified past incidents and the source snapshot available at the corresponding investigation time. Exclude current incident, duplicate copies, its later write-up and its fixes. Split incident families and versions across tuning and evaluation. Have reviewers label the acceptable analogue(s), hard negatives, whether no useful analogue exists, the distinguishing current observation and pinned supporting span. Keep private labels separate from retrieval data.
2. Give the same agent the same permitted corpus, task, model, stopping rule, time/token budgets and tool output cap. Compare competent `rg` with follow-up file reads, exact/scoped traversal plus BM25, vector-only and hybrid. Randomize order and blind arm names. Record per-query paired differences in top-three recall, correct cited span, wrong-cause transfers, false positives on no-analogue cases, total agent input/output tokens including follow-up reads, elapsed p50/p95 and embedding/build cost. Report model/provider cost separately and amortize build cost at observed query volume. Keep failures.
3. Proposed go/no-go, fixed before opening held-out labels: zero unpermitted disclosures or false admissions in adversarial cases. Hybrid must sustain correct cited answers and avoid extra wrong-cause transfers. Require improved top-three recall on paraphrases and a lower paired median token cost per correctly solved investigation than the better baseline. Report intervals and absolute counts, including unsolved investigations, so denominator choices cannot turn failures into savings. Require an acceptable p95 on the target WSL machine. Inconclusive evidence leaves hybrid off. A better lexical-only result is a successful experiment.
4. Do not count the [synthetic cases](../qualification/similar-cases/fixtures/pilot.json) as a held-out benchmark. They exercise wrong-revision, ambiguous cause, draft, restricted and empty-result behavior. A local hash-embedding mock can test wiring only.

**Implementation order.** P03C remains first for proof vocabulary and P05C for exact reader behavior. Reuse P01O for pinned engine/native snapshot qualification. Add the candidate retrieval lemmas to the proof agent’s mapping. After the citation and native gates, run the scoped lexical baseline; enable hybrid only on a measured win. P11 retains source-pinned negative tests, Rust refinement, profile-instance records and replay. Keep each parser, scoped adapter, ranker and witness resolver small, independently testable and within the existing quality budgets. A product gate stays pending if its evidence is missing.
