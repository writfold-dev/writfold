# Writfold guides

> **Status:** built in v0.6.0-dev.4: delivery modes for agents (a mode's `waivable` and a mode gate's `accept`, withdrawing a draft, guard routes that read the posted text, `deliver payload`, `deliver posted` and `posted:<mode>`, `deliver match`, `deliver modes`, findings with a next step), see [Delivery modes](delivery-modes.md); more of the core proved in Lean, see [assurance](assurance.md); a second clone is never judged against the first, faster `find`, and `gate lines` agreeing with the plan summary. Built in v0.6.0-dev.3: your own policy for runs ([Policy](policy.md)): which outcomes a gate accepts, whether checklist items may be not-applicable or none-found, required steps that cannot be skipped, the policy pinned to each run with drift reported, plain plan summaries (complete, complete with exceptions, policy moved, closed incomplete), `kb init` and `kb policy`; more of the core proved in Lean ([assurance](assurance.md)). Built in v0.6.0-dev.2: every file Writfold reads (gates, guard rules, plans, delivery modes, deny lists, kind declarations, JSON-lines files, records) reports errors with the file, line and column, the source line and a suggestion, and `writfold kb lint` checks them all, see [Errors](errors.md). Built in v0.6.0-dev.1 (guard rules read a command as the shell splits it and judge the repository it acts on, `gates.met` over an empty set refuses, `mode = "audit"` and the guard log, guard conformance cases, see [Hooks](hooks.md); the `normalized`, `prefix` and `heading` lookup tiers, `matched_on` and `find --eval`, see [kb-layout](kb-layout.md) and [validation](validation.md); `runs --idle` and `kb delta`, see [feeding-back](feeding-back.md); a delivery as a plan step's gate, `deliver:<mode>`, and the re-check of cited evidence on every read, see [run-graph](run-graph.md#a-delivery-as-a-steps-gate) and [delivery-modes](delivery-modes.md#on-a-plan-step); `writfold watch` in plain words by default, with the exact wording on `d`, see [Watching a run](watch.md)). Each page below says what is built and what is planned. The assessed gate (Weft) and `kb edit apply` (Splicery) were removed on 21 November 2026, after Tuft's `writfold tuft` on 16 November; retrieval and edit receipts that earlier runs recorded are still read.

These pages hold the full skeletons the website only sketches: file layouts, complete configuration files and real command output. The output comes from an invented demo knowledge base (`harbor`); run IDs and digests are real, local paths are cut to `…`.

A `toml` block in these pages is parsed by the real parser in a test (`crates/writfold-kb/tests/guide_toml.rs`). A block under a `<!-- planned -->` marker is a sketch of a format that is not built; the same test checks that today's parser still refuses it, so the marker cannot outlive the feature.
